# Timeline of serving a request


1. `jadelet.JADE.TaskReceiver` When a request arrives the node by accessing the service interface

    ```golang
    jadelet.JADE.TaskReceiver(w rest.ResponseWriter, r *rest.Request) 
    ```

    + Summary: Just to process the incoming raw request data, such as extracting request data, validating authorities, validating data structure of the request, and forward the valid request to a subsequent inner interface `jadelet.JADE.evaluateTasks`

    + File location: `aces/jade-go/jadelet/interfaces-control-downstream.go`

    + Trace point: `task arrival` in the decoded incoming task data structure `scheduler.TaskDispatchingItem`, which is an property of `scheduler.TaskCacheTaskItem`

2. `jadelet.JADE.evaluateTasks` Classifying the incoming request and forwarding to corresponding interfaces

    ```golang
    jadelet.JADE.evaluateTasks(tasklist map[string]*scheduler.TaskDispatchingItem)
    ```

    + Summary: Here the request is classified according to its data structure, then forward `aggregative` requests to a subsequent inner interface `jadelet.JADE.evaluateAggregativeTasks`

    + File location: `aces/jade-go/jadelet/background-downstream-task-planner.go`

    + Input data structure: `tasklist map[string]*scheduler.TaskDispatchingItem`

        - located at `aces/jade-go/scheduler/task-dispatching-item.go`

    + Output data structure: `void`


3. `jadelet.JADE.evaluateAggregativeTasks` When a request is classified as `aggregative` request, it'll be forwarded here to process

    ```golang
    jadelet.JADE.evaluateAggregativeTasks(tasklist map[string]*scheduler.TaskDispatchingItem)
    ```

    + Summary: This interface behave differently under two different roles

        - in an `aggregator` node which has one or more subnodes

            * from the `jadelet.JADE.PodCache` get a living pod for `aggregator` task, according to the requirements of resources for the specific application

                - allocate an aggregator pod according to the requirements for the specific application, if no living `aggregator` pod exist, or none of the existing living pods match the requirements or the application

                - if still no living pod, fail the request

            * cache the aggregator task on `self-node` using the interface `jadelet.JADE.TaskCache.CacheTaskForSubnode`

                - a timestamp `ArriveTimestamp` is created in the newly cached subtask item `TaskCacheSubtaskItem`, which means the subtask is cached on the node at this time

            * set next hop for the cached task using `scheduler.TaskDispatchingItem.SetReportToForModule` according to the requirements of the request

        - in an `worker` node which do not have any subnodes, just accept the request

        - forward accepted requests to the interface `jadelet.JADE.downstreamPropagating` to process

    +  File location: `aces/jade-go/jadelet/background-downstream-task-provisioning-aggregative.go`

    + Input data structure: `tasklist map[string]*scheduler.TaskDispatchingItem`

        - located at `aces/jade-go/scheduler/task-dispatching-item.go`

    + Output data structure: `void`

    + Trace point: `ArriveTimestamp` in cached subtask item `scheduler.TaskCacheSubtaskItem` during the invocation of the method `jadelet.JADE.TaskCache.CacheTaskForSubnode`

4. `jadelet.JADE.downstreamPropagating` When a request is accepted by the node, no matter what kind of the node is, either aggregator or worker node, the request will be further processed here.

    ```golang
    jadelet.JADE.downstreamPropagating(tasklist map[string]*scheduler.TaskDispatchingItem)
    ```

    + Summary: Selecting available subnodes to dispatch subtasks, which might including worker nodes, or aggregative nodes that going to be propagated to. Basically, this is the procedure for worker pods only, because the aggregator pod is already processed during the previous step.

        - select available subnodes according to requirements of capabilities

        - search the PodCache for available pod for each selected subnode

            * if no available pod and it is happen to be on Self-Node, then allocate pod on Self-Node

        - for each available subnodes

            * if the node itself in the available subnodes (two possibilities: the aggregator node itself, and a worker node which received the propagated request from its upper node)

                - then get pod or provision one if not exist

            * if not the node itself

                - then cache the task with empty pod

                - mark the node as `target nodes` to propagate the request

                - and wait for the corresponding subnode report its pod and do further completion.

        - for each `target nodes`

            * dispatch the request to the target node using interface `jadelet.JADE.dispatchTasks`, which is identical of sending request to a node via network request

        - if the node is not an aggregative node, report the allocated/existing pod

            * then the node is going to feedback its acceptance of the request, i.e., reporting its allocated or existing pod

                - feedback is invoking the `jadelet.JADE.CollectProvisioning` interface via network

        - if the request is ready to process, which all subnodes have previous cached pods

            * go to `jadelet.JADE.checkTaskStatus` interface for that task

            * otherwise this interface would be invoked when the corresponding subnode reported its allocated pod

    + File location: `aces/jade-go/jadelet/background-downstream-task-provisioning-aggregative.go`

    + Input data structure: `tasklist map[string]*scheduler.TaskDispatchingItem`

        - located at `aces/jade-go/scheduler/task-dispatching-item.go`

    + Output data structure: `void`

    + Trace point: `ArriveTimestamp` in cached subtask item `scheduler.TaskCacheSubtaskItem` during the invocation of the method `jadelet.JADE.TaskCache.CacheTaskForSubnode`

5. `jadelet.JADE.dispatchTasks` Just invoke the target node's TaskReceiver interface via network

    ```golang
    jadelet.JADE.evaluateTasks(nodeID string, tasksToDispatch []*scheduler.TaskDispatchingItem)
    ```

    + Summary: Just invoke the target node's TaskReceiver interface via network

    + File location: `aces/jade-go/jadelet/background-downstream-task-planner.go`

    + Input data structure: `tasklist map[string]*scheduler.TaskDispatchingItem`

        - located at `aces/jade-go/scheduler/task-dispatching-item.go`

    + Output data structure: `void`

6. `jadelet.JADE.CollectProvisioning` for collecting the reports of subnodes, when the subnode has gone through from 1 to 4 successfully or failed

    ```golang
    jadelet.JADE.CollectProvisioning(w rest.ResponseWriter, r *rest.Request)
    ```

    + Summary: for collecting the reports of subnodes, when the subnode has gone through from 1 to 4 successfully or failed

        - if the reported pod is nil, means the subnode failed to allocate resource for the request, 

            * then reject the request

            * set the task as failed

            * record the timestamp as task finished by updating the `FinishTimestamp` property of `scheduler.TaskCacheTaskItem`

        - otherwise

            * update the previously cached subtask for the corresponding subnode with the reported pod
            
            * invoke `jadelet.JADE.checkTaskStatus` to check if the request is ready for executing

    + File location: `aces/jade-go/jadelet/background-downstream-task-planner.go`

    + Input data structure: `tasklist map[string]*scheduler.TaskDispatchingItem`

        - located at `aces/jade-go/scheduler/task-dispatching-item.go`

    + Output data structure: `void`

    + Trace points: 

        - (only for rejected request) `FinishTimestamp` in cached subtask item `scheduler.TaskCacheSubtaskItem` during the invocation of the method `jadelet.JADE.TaskCache.CacheTaskForSubnode`


7. `jadelet.JADE.checkTaskStatus` Check if a request is ready for executing, considering whether its subnodes all reported successfully allocated pods or not

    ```golang
    jadelet.JADE.checkTaskStatus(taskKey string)
    ```

    + Summary: Check if a request is ready for executing, considering whether its subnodes all reported successfully allocated pods or not

        - check if all its subtasks have the status of `accepted`

            * if no, do nothing, there will be other triggers from the reports of subnodes

            * if yes

                - set the task as running

                - record the timestamp as the beginning of dispatching by updating the `DispatchTimestamp` property of `scheduler.TaskCacheTaskItem`

                - gather the information of subtasks on workers, send it to the aggregator pod, which will further cache this information in its own task cache

                - update the `EnqueueTimestamp` and `DispatchTimestamp` of the aggregator subtask `scheduler.TaskCacheSubtaskItem`

                - dispatch the aggregator subtask via network invoking its interface provided by `jadesdk`, together all the information of its subtasks on corresponding worker nodes

                - dispatch each worker subtask (enqueue to corresponding pod's queue)

                    * if the task is for simulation and is supposed to generate service time according to certain statistic distribution, then generate a random service time span for the subtask

                    * enqueue the task into corresponding pod queue, record the timestamps:

                        - `ArrivalTime` of `scheduler.PodQueueItem`

                        - `enqueueTime` of `scheduler.PodQueueItem` which is a logic clock of the queue


    + File location: `aces/jade-go/jadelet/background-downstream-task-dispatcher-aggregative.go`

    + Input data structure: `taskKey string`

    + Output data structure: `void`

    + Trace points: 

        - `DispatchTimestamp` in cached subtask item `scheduler.TaskCacheSubtaskItem` during the invocation of the method `jadelet.JADE.TaskCache.CacheTaskForSubnode`

        - `EnqueueTimestamp` and `DispatchTimestamp` of the aggregator subtask `scheduler.TaskCacheSubtaskItem`

        - `ArrivalTime` of `scheduler.PodQueueItem` for each worker subtask


8. `jadelet.JADE.routimeForPodQueues` the daemon thread of dequeuing each queue

    ```golang
    jadelet.JADE.routimeForPodQueues(intervalMicroseconds int)
    ```

    + Summary: the daemon thread of dequeuing each queue

        - for each pod in cache, if the pod is idle, then dequeue and dispatch the head of the queue

            * invoking `jadelet.JADE.dispatchSubtask` interface

    + File location: `aces/jade-go/jadelet/background-downstream-task-dispatcher-aggregative.go`


9. `jadelet.JADE.dispatchSubtask` dequeuing a pod queue and dispatching a subtask to that worker pod

    ```golang
    jadelet.JADE.dispatchSubtask(pod *kernel.Pod)
    ```

    + Summary: dequeuing a pod queue and dispatching a subtask to that worker pod

        - set the pod as busy

        - dequeue the queue of the pod

            * record the timestamp `DispatchTime` of the `scheduler.PodQueueItem`

            * record the logic clock `dequeueTime` and calculate `QueueLength`

            * invoke `scheduler.TaskCache.DispatchedPodQueueItem` to record timestamps of the subtask


    + File location: `aces/jade-go/jadelet/background-downstream-task-dispatcher-aggregative.go`

    + Trace points:

        - `DispatchTime` of the `scheduler.PodQueueItem`


10. `scheduler.TaskCache.DispatchedPodQueueItem` record timestamps of the subtask

    ```golang
    scheduler.TaskCache.DispatchedPodQueueItem(pod *kernel.Pod, item *PodQueueItem
    ```

    + Summary: record timestamps of the subtask

        - `EnqueueTimestamp` of `scheduler.TaskCacheSubtaskItem` = `ArrivalTime` of `scheduler.PodQueueItem`

        - `DispatchTimestamp` of `scheduler.TaskCacheSubtaskItem` = `DispatchTime` of `scheduler.PodQueueItem`

        - `QueueingTime` of `scheduler.TaskCacheSubtaskItem` = `DispatchTime` - `ArrivalTime` of `scheduler.PodQueueItem`

        - `QueueLength` of `scheduler.TaskCacheSubtaskItem` = `QueueLength` of `scheduler.PodQueueItem`

    + File location: `aces/jade-go/scheduler/task-cache-interface.go`

    + Trace points:

        - `EnqueueTimestamp` of `scheduler.TaskCacheSubtaskItem` = `ArrivalTime` of `scheduler.PodQueueItem`

        - `DispatchTimestamp` of `scheduler.TaskCacheSubtaskItem` = `DispatchTime` of `scheduler.PodQueueItem`

        - `QueueingTime` of `scheduler.TaskCacheSubtaskItem` = `DispatchTime` - `ArrivalTime` of `scheduler.PodQueueItem`

        - `QueueLength` of `scheduler.TaskCacheSubtaskItem` = `QueueLength` of `scheduler.PodQueueItem`


11. `jadesdk.JadeSDK.createHTTPHandler` serve the app's subtask dispatched by the scheduler

    ```golang
    jadesdk.JadeSDK.createHTTPHandler(moduleName string, moduleInst interface{}, moduleType AppModule)
    ```

    + Summary: serve the app's subtask dispatched by the master node, and record time spans of the service

        - different modules
        
            * for aggregator subtask

                - decode the result of worker subtask

                - do whatever it need to do with the result

                - cache the excution result for future usage

                - if all workers are done, 

            * for worker subtask
                
                - decode the subtask

                - execute the subtask

                - record the execution time as `service time`

        - when module is done

            * if there is any error, then report the error to master node

            * forward result to next hop, which is specified as `reportTo` in the request

                - record the `ForwardTime`

            * report to master node, together with all the time spans, except the last communication time between master node

    + File location: `aces/jadesdk/http_server_routes_app.go`

    + Trace points:

        - `ServiceTime` of the `scheduler.TaskCacheSubtaskItem`

        - `ForwardingTime` of the `scheduler.TaskCacheSubtaskItem`


12. `jadelet.JADE.CollectAppMsg` collect the reports of applications, when any subtask finished

    ```golang
    jadelet.JADE.CollectAppMsg(w rest.ResponseWriter, r *rest.Request)
    ```

    + Summary: collect the reports of applications, when any subtask finished

        - if the task report it has failed, then mark the task as failed and update the timestamp of finished

            * update `FinishTimestamp` of `scheduler.TaskCacheTaskItem`

        - call `scheduler.TaskCache.SaveResultFromApp` to update task result and timestamps

        - set the pod queue as idle

        - check the task, if finished then update `FinishTimestamp`

    + File location: `aces/jade-go/jadelet/interfaces-data-upstream.go`

    + Trace points:

        - `FinishTimestamp` of `scheduler.TaskCacheTaskItem`


13. `scheduler.TaskCache.SaveResultFromApp` update subtask result and timestamps

    ```golang
    scheduler.TaskCache.SaveResultFromApp(taskKey string, subtaskKey string, status TaskStatus, result interface{}, stat *jadesdk.StatItem)
    ```

    + Summary: update subtask result and timestamps

        - update the subtask's status according to the result reported from app

        - update `FinishTimestamp` of `scheduler.TaskCacheSubtaskItem`

        - update `ForwardingTime` of `scheduler.TaskCacheSubtaskItem` according to the `stat` data reported from app

        - update `ServiceTime` of `scheduler.TaskCacheSubtaskItem` according to the `stat` data reported from app

        - update `ReceivePackageSize` of `scheduler.TaskCacheSubtaskItem` according to the `stat` data reported from app

         - update `RequestTime` = `FinishTimestamp` - `DispatchTimestamp` of `scheduler.TaskCacheSubtaskItem`

         - update `RTT` = `RequestTime` - `ServiceTime` - `ForwardingTime` of `scheduler.TaskCacheSubtaskItem`, **which actually should named `CommunicationTime`**

         - estimate `RequestTime` = `RequestTime` - `RTT`/2


    + File location: `aces/jade-go/scheduler/task-cache-interface.go`

    + Trace points:
        
        - update the subtask's status according to the result reported from app

        - `FinishTimestamp` of `scheduler.TaskCacheSubtaskItem`

        - `ForwardingTime` of `scheduler.TaskCacheSubtaskItem` according to the `stat` data reported from app

        - `ServiceTime` of `scheduler.TaskCacheSubtaskItem` according to the `stat` data reported from app

        - `ReceivePackageSize` of `scheduler.TaskCacheSubtaskItem` according to the `stat` data reported from app

        - `RequestTime` = `FinishTimestamp` - `DispatchTimestamp` of `scheduler.TaskCacheSubtaskItem`

        - `RTT` = `RequestTime` - `ServiceTime` - `ForwardingTime` of `scheduler.TaskCacheSubtaskItem` , **which actually should named `CommunicationTime`**
